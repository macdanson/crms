# Access matrix (Phase 0)

**Status: DRAFT and provisional. The institution must approve the final roles and permissions (§2.2, §7.1).** Written for the project owner, legal team and security stakeholders.

The table below is generated from the code by `php artisan access:matrix`, so it cannot drift from what the software does. Regenerate it after any change.

## What a permission does not do

A permission never gives access to a record by itself. To see a case, a user also needs one of these:

| Route to a case    | Permission            | Also requires                                    |
| ------------------ | --------------------- | ------------------------------------------------ |
| National           | `cases.view.national` | An unexpired, time-limited role                  |
| District           | `cases.view.district` | The case is in the user's district               |
| Station            | `cases.view.station`  | The case is at the user's station                |
| Assignment         | `cases.view.assigned` | A current assignment to that case                |
| Exceptional access | None                  | Approved by another officer, and not yet expired |

District and station routes do not reach **restricted** cases unless the role also holds `cases.view.restricted`.

A person is visible when they are linked to a case the user can see, or registered in the user's scope, or registered by the user at their current station. All of this also needs `persons.view`.

## Rules that apply to every role

- An account that is suspended, deactivated or pending has no permissions, whatever roles it holds.
- Nobody can change their own roles, placement or status.
- Technical roles hold no operational permissions (§7.2).
- A second officer is required for: approving exceptional access, approving large exports, and verifying court outcomes.
