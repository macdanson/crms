01Brand foundations

CRMS is an operational tool for police officers handling highly sensitive personal data. The brand must signal official authority and calm reliability, never drama. It is a sub-brand of the Uganda Police Force: it borrows the crest's symbols and colours but is its own mark, so the official force emblem keeps its ceremonial role.

Authoritative

Official, structured, unmistakably a state system. Navy dominates.

Trustworthy

Plain language, predictable layouts, no hidden behaviour.

Accountable

Constant, quiet reminders that access is recorded and audited.

Fair

Neutral presentation of people. An allegation never looks like a conviction.

02Logo system

Four approved artworks. Always use the supplied files or the AppLogo / AppLogoMark Vue components; never redraw, retype or recolour them.

Primary lockup · crms-logo.svg. Mark, wordmark and descriptor for light backgrounds. Default choice.

Reversed lockup · crms-logo-reversed.svg. For Ink and Crest Blue backgrounds (sign-in panel, sidebar).

Full mark · crms-mark.svg. Keyline and laurel; use at 32 px and above.

Compact mark · favicon.svg. No keyline or laurel, heavier crown; for 16–31 px (favicons, app bar, avatars).

Monochrome · crms-mark-mono.svg. One colour, for stamps, fax/photocopy, embossing and print watermarks.

On Crest Blue. The gold keyline separates the shield from same-colour backgrounds; no extra outline is needed.

Clear space and minimum size

Keep clear space equal to ¼ of the mark's height (the crane head's width) on all sides. Nothing — text, edges, other logos — enters the hatched zone.

Misuse

Do

  • Use the reversed lockup on navy, the primary lockup on white or Surface.
  • Switch to the compact mark below 32 px.
  • Pair the mark with the force name only through the official lockup.

Don't

  • Recolour, add gradients, shadows, outlines or rotate the mark.
  • Place the full-colour mark on photographs or busy patterns.
  • Combine the CRMS mark with the official force emblem in one lockup.
  • Use red anywhere else in the mark or as a background behind it.

03Colour

A disciplined palette: Crest Blue carries the brand, Crane Gold marks honour and focus, and Signal Red is kept for danger only. Roughly 60% neutrals · 30% blue · 10% gold, with red under 1%.

Crest Blue ramp

Tailwind tokens crest-50 … crest-950. Element Plus tints (--el-color-primary-light-3 … 9, dark-2) are mixed from crest-600 with white/black, so components always stay on-brand.

Semantic colours

Do

  • Use Signal Red only for errors, destructive actions and security alerts.
  • Use Gold for focus rings, active-nav indicators and the motto: small, deliberate accents.
  • Pair every status colour with an icon or text label, never colour alone.

Don't

  • Colour people or person records red/green by their role in a case (suspect, victim). Roles are neutral tags.
  • Use Gold for body text on white (2.4:1 fails); use gold-700 instead.
  • Introduce new hues for modules. Differentiate with icons and labels.

04Typography

Inter for all interface text: neutral, highly legible at small sizes, with excellent number shapes. JetBrains Mono for anything an officer must read back or compare character by character: case references, force numbers, IP addresses, codes. Both are self-hosted at build time (no third-party font requests).

05Interface system

The UI is built with Element Plus, themed through CSS variables in resources/css/app.css, with Tailwind for layout. Element Plus is loaded in its own cascade layer (above preflight, below utilities), so Tailwind classes can adjust components and brand tokens override both.

Spacing

4 px base grid. Card padding 20 px; section gap 24 px; page gutter 16 px (mobile) to 32 px.

Shape

Radius 6 px controls · 10 px cards · 16 px hero panels. Shadows only for floating layers (dialogs, menus).

Sizes

Controls 36 px default, 44 px large on sign-in forms (touch target ≥ 44 px).

Components

Pattern Rule
One primary per view Each form or card has at most one Crest Blue button. Destructive actions use type="danger" plain and always confirm through ElMessageBox.
Accountability banner The app shell always shows "Authorised use only · Activity is recorded and audited". Sign-in pages carry the full notice.
Errors Server validation is shown on the field (ElFormItem :error). Toasts (ElMessage) only confirm completed actions.
Sensitive values Identifiers are masked by default (CM***********89). Full values are never sent to the browser unless the officer is authorised and the reveal is audited.
Idle timeout A gold timer dialog warns 60 s before an idle sign-out, offering "Stay signed in" and "Sign out now".
Upcoming modules Shown disabled with a neutral "Soon" tag, never as broken links.

06Voice & content

Write like a calm, competent senior officer: direct, respectful and precise. Officers read CRMS at busy front desks on shared terminals.

Write Not
Sign in Login / Log on
Your session ended because your account is no longer active. Error 403: Unauthorised user
Person linked as suspect in CRB 1234/2026 Criminal / offender
Verified conviction · Court ref … Guilty (without a verified source)
If that email belongs to an account, a link is on its way. No account found for that email
Principles
  • Sentence case everywhere; no ALL CAPS except overlines.
  • Lead with the outcome, then the next step.
  • Never reveal whether an account exists to someone not signed in.
  • Notifications (email/SMS) stay generic: no names, NINs, allegations or case details.
  • British English spelling (organisation, authorise), en-GB dates: 2 Nov 2026, 14:05.
